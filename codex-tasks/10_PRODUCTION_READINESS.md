# 10 生产上线任务清单

在执行本步骤前，请先完成 `09_QA_AND_DELIVERY.md`。

## 目标

把当前展示型 Astro 静态站完善为可公开上线、可接收真实询盘、可统计转化并可持续维护的生产级中文独立站。

目标域名：

```txt
https://cn.hihoneycomb.com/
```

## 执行原则

1. 按 P0、P1、P2 顺序执行，P0 未完成前不得宣布生产就绪；
2. 不编造认证、检测数据、客户案例、设备参数、联系方式或备案信息；
3. 需要企业提供的资料必须标记为“待人工提供”，不得用占位内容冒充正式内容；
4. 每完成一项都要执行对应验收，不只修改代码；
5. 保持静态优先，只有询盘、附件上传或必要集成才增加服务端能力；
6. 所有密钥、邮箱凭证和第三方令牌只能使用环境变量，不得提交到 Git。

## P0：正式上线阻断项

### 1. 修复移动端横向溢出

- [ ] 修复 390px 宽度下页面 `scrollWidth` 大于视口的问题；
- [ ] 移动端 Header 改为可用的折叠菜单，不能依赖超宽横向导航；
- [ ] 参数表在小屏幕下改为响应式卡片或局部可滚动区域，不能撑宽整个页面；
- [ ] 检查首页、产品页、联系页和新闻页在 320px、390px、768px 下的布局；
- [ ] 所有按钮和导航项具备足够点击区域，键盘焦点清晰可见。

验收标准：

```txt
document.documentElement.scrollWidth === window.innerWidth
```

允许明确设计为横向滚动的局部组件内部滚动，但页面根节点不得横向滚动。

### 2. 替换全部占位图片和占位文案

- [ ] 替换首页轮播图；
- [ ] 替换产品详情页产品图；
- [ ] 替换工厂、设备、工艺和应用现场图片；
- [ ] 替换新闻页展会图片；
- [ ] 删除页面中“占位图”“后续替换”等对外可见文案；
- [ ] 为真实图片补充准确的中文 `alt`；
- [ ] 生成正式 Open Graph 分享图；
- [ ] 图片输出 WebP/AVIF 或经过压缩的 JPEG/PNG，并设置尺寸避免布局偏移。

待人工提供：真实产品、工厂、设备、工艺、展会和资质照片，以及图片使用授权确认。

### 3. 建立真实询盘闭环

- [ ] 联系页增加在线询价表单；
- [ ] 字段至少包含联系人、公司、电话/邮箱、产品用途、关键参数、数量和留言；
- [ ] 支持上传 PDF、DWG/DXF、图片或压缩包等图纸附件；
- [ ] 设置文件类型、大小、数量限制，并在服务端校验；
- [ ] 接入真实邮件通知或 CRM/工单系统；
- [ ] 提交成功后展示明确结果并生成可追踪的询盘编号；
- [ ] 失败时保留用户已填写内容并显示可操作的错误提示；
- [ ] 增加 honeypot、速率限制和 CAPTCHA 等反垃圾措施；
- [ ] 保留电话和邮件作为备用联系渠道；
- [ ] 不在前端暴露邮件服务密钥。

验收标准：使用测试询盘完成“填写、附件上传、提交、业务邮箱/CRM收到、成功页展示、统计事件记录”的全链路测试。

### 4. 核验企业资料和商业声明

- [ ] 核验公司全称、地址、电话、邮箱和成立年份；
- [ ] 核验 5000 平方米生产基地声明；
- [ ] 核验 AS9100、GJB 9001C、ISO 9001、高新技术企业等资质；
- [ ] 核验材料、设备、工艺能力、尺寸范围和精度参数；
- [ ] 核验新闻事件、日期、地点和参展信息；
- [ ] 为证书、报告和参数记录内部资料来源及有效期；
- [ ] 无法提供证据的声明应删除或改为不承诺具体结果的表述。

待人工提供：营业执照信息、有效证书、检测报告、设备清单、参数依据和新闻证明材料。

### 5. 完成域名、备案和法务内容

- [ ] 确认正式部署区域和主体；
- [ ] 中国大陆服务器部署时完成 ICP 备案并展示真实备案号及链接；
- [ ] 按要求完成公安备案并展示真实备案信息；
- [ ] 非大陆部署时删除“备案号预留”，不得保留占位文字；
- [ ] 增加隐私政策页面；
- [ ] 增加网站使用条款或免责声明页面；
- [ ] 在询盘表单附近说明数据用途、保存方式和联系渠道；
- [ ] 使用非必要 Cookie/第三方追踪时增加适用的同意机制。

## P1：生产质量加固

### 6. 安全和依赖治理

- [ ] 升级 Astro 到已修复当前安全公告的受支持版本，并完成回归测试；
- [ ] `npm audit` 不得存在未评估的高危或严重漏洞；
- [ ] Nginx 或 CDN 配置 `Content-Security-Policy`；
- [ ] 配置 `Strict-Transport-Security`，仅在 HTTPS 全面生效后启用；
- [ ] 配置 `X-Content-Type-Options: nosniff`；
- [ ] 配置 `Referrer-Policy` 和合理的 `Permissions-Policy`；
- [ ] 限制表单请求大小、上传类型和请求频率；
- [ ] Docker 基础镜像使用受支持版本，并建立定期升级机制；
- [ ] 检查仓库中不存在密钥、令牌、邮箱密码和客户文件。

### 7. SEO 完整性

- [ ] 每页 title 和 description 唯一且与搜索意图一致；
- [ ] 每页只有一个主要 H1；
- [ ] canonical 指向当前中文正式 URL；
- [ ] hreflang 只指向真实存在且语义对应的英文页面；
- [ ] 没有对应英文页时，不要统一错误指向英文首页；
- [ ] sitemap 由构建流程自动生成或自动校验，避免人工漏页；
- [ ] 产品页完善 Product、Breadcrumb 和 FAQ 结构化数据；
- [ ] 新闻页完善 NewsArticle 数据和真实图片；
- [ ] 404 页面返回真实 HTTP 404 状态；
- [ ] 配置百度搜索资源平台、Bing Webmaster Tools 和 Google Search Console；
- [ ] 提交 sitemap 并记录验证状态。

### 8. 数据统计和转化追踪

- [ ] 确定并接入百度统计、GA4 或合规的同类工具；
- [ ] 记录在线询盘提交成功事件；
- [ ] 记录电话点击、邮箱点击、附件上传和主要 CTA 点击；
- [ ] 区分正式流量、内部访问和测试提交；
- [ ] 定义转化率、有效询盘率、产品页到询盘页点击率等核心指标；
- [ ] 验证统计事件只触发一次且不包含敏感表单内容；
- [ ] 建立月度流量和询盘复盘方式。

### 9. 自动化质量保障

- [ ] 配置 GitHub Actions；
- [ ] Pull Request 和主分支推送时执行 `npm ci`；
- [ ] 执行 `npm run build`；
- [ ] 增加格式、类型或静态检查；
- [ ] 增加站内死链检查；
- [ ] 增加 title、description、H1、canonical、图片 alt 和 sitemap 自动检查；
- [ ] 使用 Playwright 覆盖首页导航、产品页、联系表单和 404；
- [ ] 增加 390px 移动端横向溢出回归测试；
- [ ] 设置 Lighthouse CI 性能、可访问性、最佳实践和 SEO 门槛；
- [ ] CI 失败时禁止生产部署。

### 10. 部署、监控和恢复

- [ ] 正式环境强制 HTTPS，HTTP 301 跳转 HTTPS；
- [ ] `www`、裸域和中文子域跳转策略唯一且明确；
- [ ] 配置 CDN、静态资源缓存和 HTML 更新策略；
- [ ] 配置 DNS、TLS 证书和证书自动续期；
- [ ] 配置站点可用性监控和 HTTPS 到期监控；
- [ ] 表单接口增加错误监控和投递失败告警；
- [ ] 保留最近可用构建产物，支持快速回滚；
- [ ] 编写部署、回滚、域名和第三方服务交接文档；
- [ ] 上线后验证 robots、sitemap、404、安全响应头和表单全链路。

- [ ] 所有 P0 项完成并留有验收记录；
- [ ] 正式环境构建和部署成功；

- [ ] 所有对外图片和文案均为正式内容；
